## 当前未发行改动：手机首屏与加载

本次优化针对首页取得之后的样式显示、程序下载与场景准备。它不能缩短浏览器尚未连接到站点时的等待，也不代表已解决跨网络连接问题。

| 项目 | 优化前 | 当前改动 |
| --- | --- | --- |
| 主入口 JavaScript | 51 个源码模块，原始字节合计约 3.51 MB | 合并、压缩为 1 个主入口 bundle，约 1.08 MB；Draco 等运行时资源仍单独加载 |
| 移动档的 13 张纹理 | 对应完整纹理原始字节约 5.91 MB | 轻量纹理约 0.67 MB，完整版本继续保留 |
| 首屏样式 | 等待独立样式表请求 | 将样式内联到首页，先显示加载状态与重试入口 |
| 进入场景 | 场景准备状态与画面显示可能不同步 | 首帧完成绘制后再撤下加载界面；加载错误显示提示，可重新载入 |

表中 MB 按 1,000,000 字节计算，是文件原始字节的比较。它不是手机测速结果，也不是 HTTP 压缩后的实际传输量；bundle 大小会随源码微调，浏览器缓存与网络压缩也会改变下载量。

窄屏触控设备默认使用「流畅」和轻量纹理；省流模式或浏览器提示内存较低时也采用该档位。选择「高画质」会重新载入页面并请求完整纹理，而不只是提高渲染分辨率。需要比较画质或加载耗时时，应记录使用的纹理档位及是否发生重载。

2026-09-17 在当前 Windows 主机用 curl 对在线首页进行两次直接访问，HTML 返回 200，总耗时约 **0.21–0.55 秒**。这只覆盖该主机当时的 HTML 响应，不测量后续资源、浏览器绘制或用户手机的实际网络。**尚未完成 iOS / Android 真机基准测试**，不能据此给出手机首屏秒数或帧率承诺。

## 两档画质

v1.0.1 修复了模式切换导致的整屏泛白，以及缩放时部分地面、植被和水反射的不连续；回归范围与实测数据见 [缩放稳定性记录](./ZOOM-STABILITY.md)。这不等同于消除所有远景细线的锯齿。

主场景「高画质」将渲染像素比上限设为 1.5，使用中等环境光遮蔽及更多近景细节。「流畅」将像素比上限设为 1，减少环境光遮蔽、阴影、远景植被和演出相关开销。两档均保留核心导航与昼夜功能。

当前加载策略还会为符合条件的设备选择轻量纹理。从该初始「流畅」档切换到「高画质」会重载并获取完整纹理；已经载入完整纹理后再降低画质，主要降低渲染开销。

像素比越高，显卡需要绘制的像素越多。放大窗口、同时打开多个三维标签页，以及烟花透明粒子叠加都可能降低帧率。使用集成显卡或高分辨率屏幕时，先选择「流畅」并缩小窗口。

## 仍可能出现的视觉局限

- 远景细线、栅栏与植物透明边缘存在锯齿或闪烁的可能。
- 不同设备的色彩、阴影精度和纹理过滤结果可能不同。
- 极近距离观察、较低画质或较高鸟瞰距离会暴露模型简化与细节裁剪。
- 缺少实测建模数据的建筑、内景和植物布局与真实地点可能不同。

## 如何提供可比较的性能反馈

### 页面打开慢

先区分页面本身迟迟未出现、加载状态长时间不变，以及场景出现后的卡顿。反馈时附页面地址、访问时间、手机型号、系统与浏览器版本、Wi-Fi／移动数据、是否首次访问、画质档位，以及是否使用浏览器省流模式。

如能提供浏览器网络记录，请分开记录 HTML 的 DNS／连接／首字节时间、首屏出现时间、脚本与素材请求、场景首帧时间。HTML 尚未返回时的等待与模型加载是不同阶段，不能用模型体积直接解释前者。

### 场景运行卡顿

请使用同一发行版本、视口和画质，在所有模型加载后分别记录：

1. 白天主城堡静止观察 30 秒。
2. 固定一条场景导航路线，自动行走 60 秒。
3. 鸟瞰整个园区，缓慢旋转 30 秒。
4. 城堡夜间演出从开始至结束。

报告应包含操作系统、浏览器版本、GPU、显卡驱动、视口尺寸、设备像素比、电源状态、是否开启硬件加速、画质档位，以及是否首次加载。记录平均帧率之外，也描述卡顿的时间点、画面现象与控制台错误。没有测量工具时，提供上述环境与复现步骤即可。

目前不将某次观测到的流畅表现外推为其他硬件的保证。
